# Architecture & Code Patterns

## Idempotent API Calls (409 Handling)
All provisioning calls (Logto apps, API resources, roles, scopes) must handle 409 Conflict by retrieving the existing resource. Enables safe `--resume` without duplicates. Pattern: POST → if 409, GET list → scan by name → return existing ID.
Source: a past review record

## Shell + Python Orchestration
Bash orchestrates (file ops, step sequencing, state persistence). Python handles HTTP/JSON complexity (Logto Management API, GraphQL). This separation keeps concerns clean and improves testability.
Source: a past review record

## Untyped Stdout Contracts
Shell+Python communication via `KEY=VALUE` stdout is brittle — if a key name changes in Python, bash `grep` returns empty with no error under `set -euo pipefail`. Prefer JSON output parsed by a single `python3 -c` call.
Source: a past review record

## Resume State Validation
Resume logic must record active flags (--no-logto, --no-railway) at bootstrap time and validate on resume. Without this, `--resume` without the original flags silently changes behavior.
Source: a past review record

## State-File Key Sync
Adding a key to `read_logto_state` output REQUIRES adding it to both the Python generation block AND the parse logic. Mismatch causes `grep` exit 1 under `set -euo pipefail`.
Source: a past review record

## Scope Naming Consistency
Template routes and registration script must use identical scope names. Template hardcodes scopes like `read`/`write`; registration creates them on the API resource. Mismatch breaks every bootstrapped app silently.
Source: a past review record

## Module-Level Side Effects
Auth middleware reading `os.environ` at import time (or instantiating JWKS client) blocks testability — tests must monkey-patch before import. Use Settings singleton instead; instantiate lazily.
Source: a past review record, fixed in 95c768b

## Directory Safety in Shell Steps
Use subshells `( cd TARGET && commands )` instead of `cd TARGET; commands; cd BACK`. If a command fails mid-step before the second `cd`, subsequent steps execute in the wrong directory.
Source: a past review record


## Logto Auth Guard: useRef(wasAuthenticated)
In SPA apps with Logto, the auth guard in ProtectedLayout must use `useRef(wasAuthenticated)` to prevent redirect loops. During Logto's async sign-in callback, `isAuthenticated` momentarily goes false — without the ref, the guard redirects back to /login mid-callback. This invariant applies to every Logto SPA app generated by the template.
Source: a past review record
